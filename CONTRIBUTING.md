# Contributing to SpectraForgeEQ

Thanks for helping improve the sound, visuals and desktop experience.

## Report a problem

Use the [bug report template](https://github.com/nathan-standafer/graphic-eq/issues/new/choose). Include:

- Your Linux distribution, desktop session, GPU and graphics driver.
- Whether you run the installed app or a development build.
- Steps to reproduce, expected behavior and actual behavior.
- For a visual issue: the scene, look, color scheme, motion/flash settings and a screenshot.
- For an audio issue: the output device, EQ preset, and whether it happens with the window hidden.

If possible, reproduce visual problems with the synthetic demo described in the
[developer guide](docs/development.md). It makes reports repeatable without needing a recording.

## Propose a change

For substantial features, start with an issue explaining the user-visible result. For a new
scene, describe how frequency, loudness and rhythm affect the picture, and how it behaves in silence.

Keep pull requests focused. Include a short description, relevant test results, and before/after
screenshots for visible changes. Avoid unrelated formatting changes.

## Verify your work

```sh
cargo test --manifest-path gpu/Cargo.toml --offline
python3 -m unittest discover -s packaging -p 'test_*.py'
```

Fetch dependencies first on a fresh checkout. Desktop lifecycle changes also need the opt-in
Cinnamon smoke test in [the developer guide](docs/development.md#desktop-smoke-test).
For renderer changes, check silence and sustained sound as well as energetic music, and inspect
both normal and minimum window sizes.

The README gallery is generated by `gpu/tools/capture-gallery.py`. Keep it representative of
the actual app and regenerate affected images when a scene changes substantially.
